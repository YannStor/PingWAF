# AI 爬虫控制（AI Crawl Control）

AI 爬虫控制回答站点面对的两个问题：哪些 AI 爬虫家族在抓取它，以及每个家族应被如何对待。模型与 Cloudflare 的 AI Crawl Control 对齐，实现建在 PingWAF 已有的站点之上：

- **家族目录**存放在控制面（`api::ai_crawl::AI_BOTS`）——数据面通过规则包接收匹配所需的 User-Agent 模式，agent 内不编译任何爬虫清单；
- 站点级**设置行**保存功能开关、默认动作与两个生成文件（`robots.txt`、`llms.txt`）；
- 按家族的**覆盖项**替换单个爬虫的默认动作；
- 家族命中产生一条 `security_events` 记录，`event_type = "ai_bot"`，动作为 `allow` / `monitor` / `block` 之一。

功能默认关闭（`enabled: false`，默认动作 `monitor`）；未启用（或没有设置行）的站点编译为零条规则，请求路径上零成本。

存储：`site_ai_crawl_settings`（每站点一行）与 `site_ai_bot_policies`（每个被覆盖的家族一行）两张表，由迁移 066 创建。

## 端点

所有端点要求管理员 JWT Bearer token（与其余 API 相同的 `AdminUser` 鉴权）；写操作要求 `write` 角色。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/sites/{site_id}/ai-crawl` | 站点的 AI 爬虫设置与按家族覆盖项列表 |
| `PUT /api/v1/sites/{site_id}/ai-crawl` | 更新设置和/或整体替换覆盖项集合 |
| `GET /api/v1/sites/{site_id}/ai-crawl/preview?file=robots\|llms` | 渲染生成文件正文而不保存（返回 `mode`、`content_type`、`body`） |
| `GET /api/v1/ai-crawl/catalog` | PingWAF 认识的爬虫家族（18 个） |
| `GET /api/v1/analytics/ai-crawlers` | 基于 `access_logs` 按家族聚合的 AI 爬虫流量 |

### `GET /api/v1/sites/{site_id}/ai-crawl`

**响应（200）：**

```json
{
  "enabled": true,
  "default_action": "monitor",
  "robots_mode": "generate",
  "robots_body": "# Generated by PingWAF\n...",
  "llms_mode": "off",
  "llms_body": "",
  "llms_include_routes": true,
  "cache_max_age": 3600,
  "content_signal_search": true,
  "content_signal_ai_train": false,
  "content_signal_ai_input": false,
  "policies": [
    { "bot_id": "gptbot", "action": "block" }
  ]
}
```

没有设置行的站点返回默认值：`enabled: false`、`default_action: "monitor"`、两个文件模式均为 `"off"`、`llms_include_routes: true`、`cache_max_age: 3600`、`content_signal_search: true`、`content_signal_ai_train: false`、`content_signal_ai_input: false`、无覆盖项。

### `PUT /api/v1/sites/{site_id}/ai-crawl`

所有字段可选；省略的字段保持原值。

| 字段 | 校验 |
| --- | --- |
| `enabled` | 布尔 |
| `default_action` | `allow` / `monitor` / `block` |
| `robots_mode` / `llms_mode` | `off` / `generate` |
| `robots_body` / `llms_body` | 最多 64 KiB（65 536 字节）；保存时会剥离所有 CR（`\r`） |
| `llms_include_routes` | 布尔——把站点已启用的路由作为链接写入生成的 llms.txt |
| `cache_max_age` | 0–86400 秒（所服务文件的 `Cache-Control: max-age`） |
| `content_signal_search` / `content_signal_ai_train` / `content_signal_ai_input` | 布尔——生成的 robots.txt 中声明的 Content Signals 行 |
| `policies` | 出现时**整体替换覆盖项集合**；每项需要目录中已知的 `bot_id`，`action` 为 `inherit` / `allow` / `monitor` / `block`；每个家族一行 |

校验失败返回 `400 bad_request`，消息指出问题字段（`unknown AI crawler '…'`、`duplicate policy for '…'`、`unknown default_action '…'`、`robots_body must be at most 65536 bytes`、`cache_max_age must be between 0 and 86400` 等）。更新成功后同时 touch 站点并通知 agent，新策略随下一个规则包到达数据面。

### 家族目录（`GET /api/v1/ai-crawl/catalog`）

18 个家族，每个包含 `id`、`operator`、`name`、`category`（`training` / `search` / `agent` / `other`）与识别用的小写 `ua_substrings`。目录是控制面常量——新增爬虫是代码变更，不是迁移。覆盖（除其他外）：GPTBot、OAI-SearchBot、ChatGPT-User（OpenAI）；ClaudeBot、Claude-User、anthropic-ai（Anthropic）；PerplexityBot；Google-Extended；Applebot-Extended；CCBot（Common Crawl）；Bytespider（字节跳动）；Amazonbot；Meta-ExternalAgent；cohere-ai；YouBot；Diffbot；ImagesiftBot；Timpibot。

## 动作与执行

请求的 User-Agent 匹配某家族的模式（不区分大小写的子串匹配）时，`action` 决定处理方式：

| 动作 | 行为 |
| --- | --- |
| `allow` | 请求放行；除常规日志外不记录 |
| `monitor` | 请求放行；写入一条 `event_type = "ai_bot"` 的 `security_events` 记录 |
| `block` | 请求被拒绝并返回 `403`（经挑战/决策管线），同时写入一条 `event_type = "ai_bot"` 的 `security_events` 记录 |

按家族的 `inherit` 表示沿用站点的 `default_action`。匹配针对原始 `User-Agent` 头进行；目录中没有任何模式是另一个模式的前缀，因此家族匹配无歧义。该判定独立于传统 bot 白名单（Bot 防护）。

## 生成的 robots.txt / llms.txt

两个文件各有一个模式：`off`（源站的同名文件——如有——原样透传）或 `generate`（由 PingWAF 提供自己的文件）。

**文件从哪来。** 正文由控制面在**配置构建期**渲染——不是按请求——并随规则包推送到数据面。数据面用精确路径的 `mock` 插件实例服务它（`/robots.txt` 与 `/llms.txt`，状态 `200`，`Content-Type: text/plain; charset=utf-8`，`Cache-Control: public, max-age=<cache_max_age>`），且注册在 WAF 之前，因此 `robots.txt` 请求在任何检测之前就被应答。空正文不会注册任何东西——源站文件照常透传。

值得了解的细节：

- **仅精确路径。** `/robots.txt` 与 `/llms.txt` 按字面匹配；子路径永远不会被拦截，请求路径上也不做任何按请求拼接。
- **CRLF 过滤。** 保存时剥离所有 CR（`\r`），构造的正文无法把头部注入带进 `mock` 响应。
- **64 KiB 上限。** 超过 `MAX_FILE_BYTES`（64 × 1024 字节）的正文以 `400` 拒绝。

### 生成的 robots.txt

`# Generated by PingWAF` / `# Site: <domain>` 头，随后每个被覆盖的家族一个 `User-agent` 块（`block` 为 `Disallow: /`，其余为 `Allow: /`），然后是通配规则（`default_action` 为 `block` 时 `User-agent: *` → `Disallow: /`，否则 `Allow: /`），以及——任一 Content Signals 开关打开时——一行 `Content-Signal: search=<yes|no>, ai-train=<yes|no>, ai-input=<yes|no>`。信号名遵循 Content Signals 约定（`content_signal_search`、`content_signal_ai_train`、`content_signal_ai_input`）。

### 生成的 llms.txt

`# <站点名>` 标题、一行指明站点与域名的摘要、可选的 `## AI crawler policy` 列表（每个覆盖项一行 `- <name> (<operator>, <category>): <action>`），以及——`llms_include_routes` 打开时——`## Pages` 列表，链接站点已启用路由的路径。

## 分析（`GET /api/v1/analytics/ai-crawlers`）

按目录中的模式匹配 `access_logs` 记录的原始 user agent 进行聚合，因此流量面板能按家族给出请求计数——即使数据早于功能启用的时间。它是只读报表；执行在数据面完成。
